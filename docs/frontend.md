# Админка и страница подписки

SPA для администраторов. Говорит только с REST API из [`api/openapi.yaml`](../api/openapi.yaml);
своей логики доступа у неё нет — всё, что она прячет, панель всё равно запрещает.

Код: `frontend/`. Стек: React 19, Vite 8, TypeScript 5.9, TanStack Query, React Router,
Tailwind 4, компоненты на Radix. Почему так — ADR-073.

## Запуск

```bash
make ui-install    # зависимости из package-lock.json
make ui-dev        # dev-сервер на 127.0.0.1:5173, /api проксируется на панель :8080
make ui-build      # tsc --noEmit и сборка в frontend/dist
make ui-api        # перегенерировать типы клиента из api/openapi.yaml
```

Панель должна быть запущена (`make run`). Первый администратор — через
`BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` или `panel admin create`.

Dev-сервер слушает **127.0.0.1**, а не `localhost`: Node разрешает `localhost` сначала в `::1`,
и сервер, слушающий только IPv6, недоступен для всего, что ходит на 127.0.0.1.

## Сессия

- **Access-токен — только в памяти.** Не в localStorage: его читает любой скрипт на странице,
  и он переживает вкладку. Перезагрузка стоит одного вызова `/auth/refresh`.
- **Refresh — httpOnly-cookie**, SameSite=Strict, путь `/api/v1/auth`. Страница её не видит и не
  должна.
- **Обновление одно на всех.** Шесть запросов, одновременно получивших 401, обновляют токен
  один раз: шесть обновлений предъявили бы один refresh-токен шесть раз, а панель считает
  повторное предъявление ротированного токена кражей и отзывает всю сессию (M2).
- **Повтор после 401** — для всех запросов, кроме четырёх, которые работают без access-токена
  (`/auth/login`, `/auth/login/mfa`, `/auth/refresh`, `/auth/logout`). Включение и выключение 2FA
  и смена пароля сдвигают отметку «токены действительны с», и запрос сразу после них — ровно
  тот, которому нужен новый токен.
- **Прокси без `changeOrigin`.** Панель отвергает обновление, если хост из Origin не совпадает с
  Host запроса; переписывание Host на адрес панели сделало бы каждое обновление межсайтовым.

## Типы API

`src/api/schema.d.ts` генерируется `openapi-typescript` из контракта и лежит в репозитории, как
код sqlc и protobuf. CI перегенерирует его и падает на расхождении — иначе изменение контракта
без перегенерации продолжило бы проходить проверку типов, но против старого контракта.

Рантайм-клиент — `openapi-fetch`: несколько сотен строк, запросы и ответы типизированы по тем же
путям, что в спеке. Ошибка панели приходит как `ApiError` с её кодом и `request_id`.

## Экраны

| Раздел | Скоуп | Что там |
|---|---|---|
| Dashboard | `stats:read` | пользователи и ноды по статусам, онлайн, трафик за день и месяц, топ потребителей, живой статус нод |
| Users | `users:read` | поиск, фильтр, сортировка; карточка: лимит, продление, сброс, отключение, ротация, подписка с QR, график за 30 дней |
| Nodes | `nodes:read` | живой статус каждые 5 с; карточка: соединение, inbound'ы, токен регистрации, график |
| Inbounds | `inbounds:read` | inbound'ы и ключи Reality |
| Hosts | `inbounds:read` | что указывается в ссылках подписки |
| Groups | `inbounds:read` | какие inbound'ы кому доступны |
| API keys | `admins:read` | ключи и их скоупы; новый ключ показывается один раз |
| Webhooks | `webhooks:read` | эндпоинты событий; секрет показывается один раз |
| Audit log | `audit:read` | фильтры, страницы по id записи |
| Account | — | пароль, 2FA с QR, выход отовсюду |

Меню показывает только разделы, которые разрешает роль. Это удобство, а не защита: панель
проверяет то же правило на каждом запросе.

## График трафика

Столбцы по дням из двух сегментов (отправлено и получено), одна ось в двоичных единицах — тех
же, в которых задаются лимиты. Пустые дни присутствуют как нули, поэтому тихий день выглядит
провалом, а не сближением соседних. Цвета — первые два слота проверенной категориальной
палитры (синий, оранжевый) с отдельными значениями для тёмной темы; обе пары проходят проверку
различимости для всех форм цветовой слепоты. Легенда всегда видна, у каждого столбца
подсказка, и есть табличное представление с теми же числами.

## Smoke-проверка

Автоматическая — `frontend/e2e/smoke.spec.ts`, Playwright, выполняется в CI (`frontend-e2e`):
вход по паролю → включение 2FA → выход → вход с паролем и кодом → создание пользователя →
копирование ссылки подписки (с чтением буфера обмена обратно) → удаление → выключение 2FA,
чтобы прогон был повторяемым. Браузеры для Playwright ставятся только на раннере CI.

## Страница подписки

Второй вход сборки: [`sub.html`](../frontend/sub.html) → [`src/sub/`](../frontend/src/sub).
Открывается по той же ссылке `/sub/<токен>`, что получает клиент: браузер (запрос с
`Accept: text/html` без `?format=`) получает страницу, клиент — профиль. В production это
правило в [`deploy/Caddyfile`](../deploy/Caddyfile), в dev — `bypass` прокси `/sub` в
`vite.config.ts`, одно и то же условие (ADR-078).

Страница берёт всё одним запросом `GET /sub/<токен>/info` — без cookie и без Referer — и
показывает статус, трафик, срок и период сброса, кнопки импорта в приложения, ссылку с
копированием, QR-код (рисуется в браузере), скачивание профилей Clash и sing-box и
раскрывающийся список отдельных серверов. Для неактивной подписки — объяснение причины;
кнопки импорта остаются: добавленная сейчас подписка заработает сама после продления. Язык —
русский или английский по языку браузера (`src/sub/i18n.ts`, словари типизированы
одинаково, пропущенная строка не скомпилируется).

Страница не грузит роутер и кеш запросов админки: React вынесен в отдельный чанк, и
`sub.html` тянет около 113 КБ gzip против ~170 КБ у админки.

### Ручной чеклист страницы

Прогнан во встроенном браузере через dev-сервер против заглушки панели, отдающей
`/sub/{token}` и `/info` по контракту (настоящий бинарник панели на этой машине блокирует
Smart App Control). Сам эндпоинт панели проверяется интеграционными тестами, а связка
Caddy → страница → панель на собранных образах — job `stack` в CI.

- [x] навигация браузера на `/sub/<токен>` отдаёт страницу, данные приходят с `/info`
- [x] маршрутизация: без `text/html` — профиль; `text/html` + `?format=clash` — профиль;
      `/info` с `text/html` — JSON; `/sub/<токен>/` со слэшем — страница
- [x] активная подписка: трафик «3.2 GiB из 10.0 GiB», срок с относительной датой, сброс
- [x] «Трафик исчерпан»: бейдж, объяснение, полная красная полоса, «Бессрочно»
- [x] неизвестный токен: «Такой подписки нет или она отозвана»
- [x] QR-код, список серверов раскрывается, кнопка копирования ссылки меняется на «Скопировано»
- [x] тёмная и светлая тема, узкий экран 375 px без горизонтальной прокрутки
- [x] в консоли только ожидаемые 404 на несуществующий токен
- [ ] английский язык — не проверялся вживую (браузер здесь русскоязычный); словарь
      типизирован по английскому

## Что пока не так

- Браузерные тесты никогда не запускались на этой машине: здесь не ставятся браузеры для
  Playwright. Первый прогон будет в CI.
- Кнопки импорта не проверены на устройствах с установленными приложениями — приёмочный
  чеклист в [`deployment.md`](deployment.md#проверка-после-установки).
