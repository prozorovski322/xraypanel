# Развёртывание

От чистого сервера до работающей подписки. Всё, что здесь описано, запускается файлом
[`deploy/docker-compose.yml`](../deploy/docker-compose.yml) и настраивается одним `.env`.

## Что получится

```
                 интернет
      ┌──────────────┼───────────────────────────┐
  80, 443 tcp/udp    │                        8443 tcp (ноды, mTLS)
      │              │                           │
 ┌────▼─────┐  edge  │                     ┌─────▼─────┐
 │   web    ├───────────── /api, /sub ────►│   panel   │──► вебхуки наружу
 │  Caddy   │  172.31.250.0/24             └─────┬─────┘
 │ UI + ACME│                                    │ db (internal)
 └──────────┘                  ┌─────────────────┼──────────────┐
                               │                 │              │
                         ┌─────▼────┐     ┌──────▼─────┐  ┌─────▼────┐
                         │ migrate  │     │ postgres   │◄─┤  backup  │
                         │ (разово) │────►│    16      │  │ pg_dump  │
                         └──────────┘     └────────────┘  └──────────┘
```

| Сервис | Образ | Что делает |
|---|---|---|
| `postgres` | `postgres:16-alpine` | единственное хранилище состояния |
| `migrate` | `…/panel` | применяет миграции и завершается; панель без него не стартует |
| `panel` | `…/panel` | REST API, `/sub`, gRPC для нод, воркеры |
| `web` | `…/web` | Caddy: сертификат, админка, страница подписки, прокси |
| `backup` | `…/backup` | дамп по расписанию, проверка, ротация, восстановление |

Наружу открыты **только** 80/443 (Caddy) и порт нод (по умолчанию 8443). HTTP-порт панели
8080 не публикуется: к ней ходят только через Caddy. Сеть `db` помечена `internal` —
у Postgres и бэкапа нет выхода в интернет, и из интернета к ним не попасть.

## Требования

- Linux x86_64 или arm64, 1 vCPU и 1–2 ГБ RAM хватает на целевой масштаб (5k
  пользователей, 30 нод). Диск — с запасом под бэкапы: дамп занимает порядок размера
  таблицы `traffic_records` за 90 дней в сжатом виде.
- Docker Engine с плагином `docker compose` v2 —
  [официальная инструкция](https://docs.docker.com/engine/install/).
- Домен, A/AAAA-запись которого **уже** указывает на сервер. Caddy получает сертификат при
  первом старте, и ACME-проверка идёт на портах 80 и 443 этого сервера.
- Открытые входящие порты: 80/tcp, 443/tcp, 443/udp (HTTP/3), порт нод (8443/tcp).

> Docker публикует порты в обход `ufw`: правила `ufw` на опубликованные контейнером порты
> не действуют. Ограничить порт нод списком адресов можно в цепочке `DOCKER-USER`. Порт
> нод безопасно держать открытым — без клиентского сертификата, выпущенного CA панели, по
> нему ничего не сделать, — но сужение до адресов нод убирает и сканирование.

## Установка

### 1. Файлы

Нужны два файла из репозитория: `deploy/docker-compose.yml` и `deploy/panel.env.example`.

```bash
mkdir -p /opt/xraypanel && cd /opt/xraypanel
# скопируйте сюда оба файла (scp, git clone — как удобно)
cp panel.env.example .env
chmod 600 .env
```

### 2. `.env`

Обязательно заполнить:

| Переменная | Как получить |
|---|---|
| `PANEL_DOMAIN` | ваш домен, например `panel.example.com` |
| `POSTGRES_PASSWORD` | `openssl rand -hex 24` — **только hex**: пароль подставляется в URL |
| `PANEL_SECRET_KEY` | `openssl rand -hex 32` |
| `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD` | первый администратор, пароль от 12 символов |
| `XRAYPANEL_VERSION` | тег релиза, например `0.12.0`. `latest` работает, но тогда обновление случится, когда пересоздастся контейнер, а не когда вы решили |

**Сохраните копию `.env` вне сервера** — отдельно от бэкапов. Без `PANEL_SECRET_KEY` дамп
базы бесполезен: не расшифровать CA, ключи Reality и секреты 2FA.

Все остальные настройки панели из корневого [`.env.example`](../.env.example) можно
добавить в тот же `.env`, они дойдут до контейнера. Не нужно задавать только то, что
compose-файл фиксирует сам: `APP_ENV=prod`, `DATABASE_URL`, `HTTP_ADDR`, `GRPC_ADDR`,
`HTTP_TRUSTED_PROXIES`.

### 3. Запуск

```bash
docker compose pull
docker compose up -d
docker compose ps
```

Порядок старта задан зависимостями: `postgres` (healthy) → `migrate` (завершился успешно)
→ `panel` (healthy) → `web`; `backup` — после `migrate`. Если `migrate` упал, панель не
стартует вовсе: `docker compose logs migrate` покажет причину.

Сертификат Caddy получает за несколько секунд. Если через минуту `https://<домен>/` не
открывается — `docker compose logs web`: почти всегда это DNS, ещё не указывающий на
сервер, или закрытый порт 80.

### 4. Первый вход

Откройте `https://<домен>/`, войдите bootstrap-администратором, включите 2FA в
Settings. Затем уберите обе строки `BOOTSTRAP_ADMIN_*` из `.env` и пересоздайте панель:

```bash
docker compose up -d panel
```

Bootstrap срабатывает только на пустой таблице администраторов, так что оставленные строки
ничего не сломают, — но пароль в `.env` на сервере лежать не должен.

### 5. Первая нода

В админке: **Inbounds** → создать inbound (для Reality — сначала ключ), **Nodes** → создать
ноду и привязать inbound, **Hosts** → как клиент увидит адрес, **Groups** → группа по
умолчанию с этим inbound'ом. Затем на ноде выпустить токен регистрации — диалог покажет
`NODE_PANEL_ADDR`, `NODE_CA_PIN` и `NODE_ENROLLMENT_TOKEN`.

На сервере ноды — [`deploy/docker-compose.node.yml`](../deploy/docker-compose.node.yml) с
этими тремя значениями. Подробности, включая требования к ноде, — в
[`docs/node-agent.md`](node-agent.md). Через несколько секунд нода в админке станет
`connected`.

### 6. Подписка

Создайте пользователя, откройте его карточку и скопируйте ссылку подписки. В браузере
ссылка открывает страницу подписки: статус, трафик, кнопки импорта, QR-код. Клиент по той
же ссылке получает профиль в своём формате ([`docs/subscriptions.md`](subscriptions.md)).

## Проверка после установки

```bash
# Сервисы живы; backup станет healthy после первого дампа.
docker compose ps

# Клиентский ответ идёт от панели, с квотой в заголовке.
curl -si -A 'v2rayNG/1.10' https://<домен>/sub/<токен> | grep -i subscription-userinfo

# Браузерный — страница от Caddy.
curl -s -H 'accept: text/html' https://<домен>/sub/<токен> | grep -o '/assets/sub-[^"]*'

# Первый бэкап снят и проверен.
docker compose exec backup backup list
```

Приёмочный чеклист клиентов (выполняется вручную, на реальных устройствах):

| Клиент | Как импортировать | Ожидается |
|---|---|---|
| v2rayNG (Android) | «+» → импорт подписки по ссылке, или кнопка на странице | серверы в списке, соединение есть |
| NekoBox (Android) | «+» → новая группа → подписка | то же |
| Clash Verge Rev / mihomo | кнопка на странице или «Профили → импорт» | профиль с группой, соединение |
| sing-box (SFA/SFI) | кнопка на странице | удалённый профиль, соединение |
| любой | пользователь `disabled` | профиль без серверов, квота видна |
| любой | ротация учётных данных | старая ссылка — 404 |

## Обновление

```bash
cd /opt/xraypanel
docker compose exec backup backup once     # свежий дамп прямо перед обновлением
sed -i 's/^XRAYPANEL_VERSION=.*/XRAYPANEL_VERSION=0.13.0/' .env
docker compose pull
docker compose up -d
```

`migrate` применяет новые миграции до старта новой панели. Миграции только вперёд
([`docs/migrations.md`](migrations.md)): откат версии — это восстановление дампа, снятого
первой командой.

Обновление образа ноды — отдельно, на каждой ноде; панель и ноды совместимы в пределах
версии протокола ([`docs/node-protocol.md`](node-protocol.md)).

## Бэкапы

Сервис `backup` снимает дамп сразу при старте (если на томе нет свежего) и затем каждые
`BACKUP_INTERVAL`. Каждый дамп:

1. пишется `pg_dump --format=custom` во временный `*.partial`;
2. **проверяется**: оглавление должно содержать таблицы панели (`goose_db_version`,
   `users`, `nodes`) — это ловит дамп не той или пустой базы; затем `pg_restore` читает
   архив целиком в `/dev/null` — это ловит обрезанный файл, который `--list` пропускает
   (проверено на `pg_restore` 16: файл, обрезанный на последнем проценте, `--list` читает
   без ошибки);
3. получает `*.sha256` в формате `sha256sum` и только после этого переименовывается в
   `panel-<UTC-время>.dump`. Файл с таким именем — всегда прошедший проверку.

Чего проверка **не** ловит: изменённых байтов внутри данных таблиц. У формата архива нет
контрольных сумм данных, и такой дамп читается и восстанавливается без ошибок — с
неверными значениями. От порчи после снятия защищает `*.sha256` (`backup verify` и
`restore` сверяют его первым делом); порчу в момент записи на диск может показать только
восстановление, поэтому пробное восстановление по разделу ниже стоит делать регулярно, а не
только в аварии.

Ротация: хранится не больше `BACKUP_KEEP` дампов и не старше `BACKUP_MAX_AGE`, но **самый
свежий не удаляется никогда** — если бэкапы месяц падают, ротация по возрасту иначе
удалила бы последнюю хорошую копию. Упавший дамп повторяется через 10 минут.

Healthcheck контейнера — `backup health`: unhealthy, если последний дамп старше двух
интервалов. `docker compose ps` покажет это без отдельного мониторинга.

| Переменная | По умолчанию | |
|---|---|---|
| `BACKUP_INTERVAL` | `24h` | как часто |
| `BACKUP_KEEP` | `14` | сколько хранить максимум |
| `BACKUP_MAX_AGE` | `720h` | сколько хранить по времени; не меньше интервала |
| `BACKUP_TIMEOUT` | `1h` | предел на один запуск `pg_dump`/`pg_restore` |

Команды:

```bash
docker compose exec backup backup list                 # дампы, новые сверху
docker compose exec backup backup once                 # снять сейчас
docker compose exec backup backup verify <файл>        # контрольная сумма + полное чтение
docker compose exec backup backup health
```

### Копия вне сервера

Том `backups` лежит на том же диске, что и база: он защищает от ошибок и неудачных
миграций, но не от потери сервера. Забирайте дампы наружу, например ежедневно с другой
машины:

```bash
ssh server 'cd /opt/xraypanel && docker compose cp backup:/backups -' | tar -x -C ./xraypanel-backups
cd xraypanel-backups/backups && sha256sum -c *.sha256
```

`docker compose cp … -` отдаёт tar-поток на stdout. Контрольные суммы проверяются
стандартным `sha256sum` на любой машине.

## Восстановление

Восстановление идёт **в новую базу**, рабочая не трогается до явного переключения. У
инструмента нет режима, в котором он может удалить или перезаписать существующую базу.

```bash
cd /opt/xraypanel

# 1. Выбрать дамп и восстановить его рядом с рабочей базой. Перед восстановлением дамп
#    проверяется (контрольная сумма + полное чтение); непроверенный не восстанавливается.
docker compose exec backup backup list
docker compose exec backup backup restore panel-20260928T030000Z.dump panel_restored

# 2. Схема восстановленной базы: версии миграций, которые она содержит.
set -a; . ./.env; set +a
docker compose run --rm \
  -e DATABASE_URL="postgres://panel:${POSTGRES_PASSWORD}@postgres:5432/panel_restored?sslmode=disable" \
  migrate migrate-status

# 3. Переключение: остановить всё, что держит соединения, и поменять базы местами.
docker compose stop web panel backup
docker compose exec postgres psql -U panel -d postgres \
  -c 'ALTER DATABASE panel RENAME TO panel_before_restore' \
  -c 'ALTER DATABASE panel_restored RENAME TO panel'

# 4. Запуск. migrate доприменит миграции, если дамп старше текущей версии панели.
docker compose up -d
```

Проверьте админку и подписки. Прежняя база остаётся как `panel_before_restore`; удалить
её — когда убедились, что всё в порядке:

```bash
docker compose exec postgres psql -U panel -d postgres -c 'DROP DATABASE panel_before_restore'
```

Если восстановленная база оказалась не той — переименуйте обратно тем же способом.

### На новый сервер

1. Установка по разделу выше, **с тем же `.env`** (прежде всего `PANEL_SECRET_KEY` и
   `POSTGRES_PASSWORD`), `docker compose up -d`. Панель поднимется на пустой базе.
2. Скопировать дамп и его `.sha256` в том бэкапов:
   `docker compose cp panel-….dump backup:/backups/` и то же для `.sha256`.
3. Шаги 1–4 восстановления выше.

Ноды переподключатся сами: их идентичность — сертификат, выпущенный CA из восстановленной
базы, а адрес панели не изменился, если DNS указывает на новый сервер.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `https://домен` не открывается, в логах `web` ошибки ACME | DNS ещё не указывает на сервер или закрыт порт 80. Caddy повторит сам |
| Всем клиентам `429` на `/sub` | панель видит всех с адреса Caddy, то есть `HTTP_TRUSTED_PROXIES` не совпадает с подсетью сети `edge` — например, `EDGE_SUBNET` поменяли, а сеть осталась прежней. `docker compose down && docker compose up -d` пересоздаст сеть (тома не трогаются) |
| `panel` не стартует, `migrate` exited 1 | `docker compose logs migrate`; частая причина — неверный `POSTGRES_PASSWORD` после смены |
| `backup` unhealthy | `docker compose logs backup`; дамп, не прошедший проверку, остаётся как `*.partial` для разбора |
| нода не подключается | [`docs/node-agent.md`](node-agent.md), раздел о диагностике; порт нод должен быть открыт |

## Что не проверено

- **Развёртывание на чистой VPS строго по этому документу** — [ПРОВЕРИТЬ]: образы,
  Caddyfile и compose-файл проверяются в CI (job `stack`: сборка трёх образов, запуск
  стека, запросы через Caddy, бэкап, проверка и восстановление), но не на реальном
  домене с Let's Encrypt.
- **Импорт в четыре клиента на реальных устройствах** — [ПРОВЕРИТЬ], чеклист выше.
