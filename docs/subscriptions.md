# Подписки и клиентские ссылки

Один набор данных о доступе пользователя рендерится в четыре формата. Код:
[`internal/sublink`](../internal/sublink).

Отдаёт их публичный эндпоинт `GET /sub/{token}` (раздел [«Эндпоинт»](#эндпоинт) ниже).

## Выбор формата

По `User-Agent`, с возможностью перебить через `?format=`.

| Клиенты | Формат |
|---|---|
| sing-box, SFI/SFA/SFM, Hiddify, Karing | `singbox` (JSON) |
| Clash, Clash.Meta, mihomo, Stash, FlClash | `clash` (YAML) |
| v2rayNG, v2rayN, Nekobox, Nekoray, Shadowrocket, Streisand, Happ, Loon, Surge, Quantumult | `base64` |
| **всё остальное и пустой UA** | `base64` |

Нераспознанный клиент получает **base64**, и это осознанно. Ошибка в сторону base64
стоит клиенту более богатого профиля; ошибка в другую сторону стоит ему
работоспособности. Асимметрия очевидна (ADR-038).

Отдельный случай: NekoBox присылает `NekoBox/Android/1.3.1 (Prefer ClashMeta Format)` —
клиент сам называет желаемый формат, и мы его уважаем. Сборка без такой подсказки
получит base64.

`?format=` принимает `base64` / `links` / `v2ray`, `clash` / `mihomo`, `singbox` /
`sing-box`, `json`. Неизвестное значение — **ошибка**, а не дефолт: опечатка в
query-параметре не должна выглядеть как успех.

## Ссылки

### VLESS

```
vless://<uuid>@<host>:<port>?<params>#<remark>
```

Имена параметров — по спецификации VLESS share link:

| Параметр | Когда |
|---|---|
| `type` | всегда: `tcp`/`ws`/`grpc`/`httpupgrade`/`xhttp` |
| `security` | всегда: `none`/`tls`/`reality` |
| `encryption` | всегда `none` (поле обязательное) |
| `flow` | только `vless+tcp+tls|reality` |
| `sni`, `fp`, `alpn` | при tls и reality |
| `pbk`, `sid`, `spx` | только reality |
| `path`, `host` | ws, httpupgrade, xhttp |
| `serviceName`, `mode` | grpc |
| `allowInsecure` | если включено на host'е |

Параметры **отсортированы по алфавиту**: ссылка, меняющая форму между запросами,
выглядит для клиента другим сервером.

### Trojan

То же, но пароль в userinfo и без `encryption`.

### Shadowsocks

```
ss://<method>:<percent-encoded serverPSK:userPSK>@<host>:<port>#<remark>
```

Только методы `2022-*`. Userinfo **не** заворачивается в base64 — SIP002 прямо
запрещает это для AEAD-2022 и требует percent-кодирования метода и пароля. Пароль —
серверный и пользовательский ключи через двоеточие (SIP023); внутреннее двоеточие
экранируется в `%3A`, поэтому парсер, режущий по первому двоеточию, не путает его с
разделителем (ADR-036).

### Кодирование

Строго как `encodeURIComponent`, чего и требует спецификация: unreserved —
`ALPHA DIGIT - _ . ! ~ * ' ( )`, всё остальное percent-encoded.

`net/url` для сборки не используется: `url.Values.Encode()` — это form-кодирование,
где пробел становится `+`, и клиент показал бы буквальный плюс в пути или в названии
сервера. Есть тест, запрещающий `+` в ссылке (ADR-037).

## Заголовки ответа

```
subscription-userinfo: upload=1073741824; download=5368709120; total=107374182400; expire=1798761599
profile-update-interval: 12
profile-title: xraypanel
content-type: text/plain; charset=utf-8
```

Все четыре поля в `subscription-userinfo` присутствуют всегда: пропущенное
показывается в клиенте как «неизвестно», а не как ноль. `total=0` означает «без
лимита», `expire=0` — «бессрочно».

`profile-title` с не-ASCII символами кодируется как `base64:<...>`: сырое UTF-8
значение в заголовке нелегально и будет искажено или выброшено по пути.

Профили Clash и sing-box дополнительно получают `content-disposition: attachment;
filename=<title>.yaml|.json` (не-ASCII — через `filename*` по RFC 2231): десктопные
Clash-клиенты берут из него имя профиля. Списку ссылок он не нужен — браузер скачал бы то,
что мог показать.

## Шаблоны

`hosts.remark` и `hosts.address` поддерживают `{USERNAME}`, `{NODE}`, `{COUNTRY}`.

Неизвестный placeholder **остаётся как есть**: опечатка проявится в клиенте видимым
`{NDOE}`, а не молчаливой дыркой в названии. Это разница между ошибкой, которую
замечают, и которую нет.

## Различия схем

Три формата называют одно и то же по-разному — поэтому это три отдельных рендерера, а
не преобразования друг из друга:

| Смысл | ссылка | Clash | sing-box |
|---|---|---|---|
| SNI | `sni` | `servername` | `tls.server_name` |
| отпечаток uTLS | `fp` | `client-fingerprint` | `tls.utls.fingerprint` |
| публичный ключ Reality | `pbk` | `reality-opts.public-key` | `tls.reality.public_key` |
| shortId | `sid` | `reality-opts.short-id` | `tls.reality.short_id` |
| порт | в authority | `port` | `server_port` |
| gRPC service | `serviceName` | `grpc-opts.grpc-service-name` | `transport.service_name` |
| пропуск проверки | `allowInsecure` | `skip-cert-verify` | `tls.insecure` |

Две особенности, которые ломают клиента молча:

- **sing-box с Reality требует блок `utls`.** Профиль без него загружается и падает на
  каждом handshake. Генератор подставляет `chrome`, если отпечаток не задан.
- **Clash и sing-box ключуют прокси по имени** и молча оставляют один из
  одноимённых. Имена делаются уникальными (`DE`, `DE (2)`, `DE (3)`), иначе
  пользователь с двумя host'ами под одним remark'ом тихо теряет один.

**xhttp в sing-box отсутствует.** Такой эндпоинт из профиля sing-box исключается: выдать
неизвестный транспорт означало бы профиль, отвергнутый **целиком**, то есть потерю всех
серверов вместо одного (ADR-039). В base64 и Clash он попадает.

## Проверка

```bash
go test ./internal/sublink/...

SINGBOX_BINARY=/path/to/sing-box MIHOMO_BINARY=/path/to/mihomo \
  go test ./internal/sublink/...
```

Без переменных проверки реальными клиентами пропускаются. Прогоняется и весь профиль
сразу, и каждый эндпоинт по отдельности (иначе видна только первая проблема), и пустая
подписка — оба клиента отвергают селектор без участников, поэтому пользователь без
доступа должен получить валидный профиль без групп, а не профиль с пустыми.

На момент M4 **sing-box 1.14.2** и **mihomo 1.19.31** принимают все шесть
генерируемых форм. Версии зафиксированы в CI.

Ссылки дополнительно зафиксированы Example-тестами: их вывод проверяется `go test`,
так что документация в godoc не может разойтись с кодом.

## Эндпоинт

Код: [`internal/httpapi/subscription.go`](../internal/httpapi/subscription.go),
[`internal/service/subscription.go`](../internal/service/subscription.go).

| Запрос | Ответ |
|---|---|
| `GET /sub/{token}` | профиль в формате по `User-Agent` или `?format=`, заголовки выше |
| `HEAD /sub/{token}` | те же заголовки без тела; не считается скачиванием |
| `GET /sub/{token}/info` | JSON для страницы подписки: статус, трафик, срок, отдельные ссылки |

Аутентификации нет: токен в пути — единственный идентификатор. Отсюда правила:

- **Неизвестный, некорректный и отозванный токен — одинаковый `404` без текста.** Токен
  отзывается ротацией учётных данных: старое значение просто перестаёт существовать.
  Токен неправильной формы отсекается до запроса в базу.
- **Неактивный пользователь получает `200` без серверов** и с `subscription-userinfo`.
  Отказ оставил бы в клиенте прежние, уже нерабочие серверы без объяснения; пустой профиль
  с квотой показывает, что трафик кончился или срок истёк. Пустой профиль валиден во всех
  форматах — оба клиента, sing-box и mihomo, это проверяют (см. «Проверка»).
- **Статус эффективный**: пользователь, уже превысивший лимит или со сроком в прошлом,
  считается `limited`/`expired`, даже если воркер принуждения ещё не успел записать это
  (он ходит раз в 30 секунд).
- `Cache-Control: no-store`: профиль — это учётные данные.
- `sub_fetched_at` обновляется только при `GET` профиля — не при `HEAD` и не при просмотре
  страницы, — чтобы «последнее обновление» в админке значило именно обновление клиентом.
- Токен вырезается из пути в логах панели (`/sub/[token]`), access-лог Caddy выключен.

### Лимит запросов

На клиентский адрес (для IPv6 — на `/64`: клиенту выдают целую подсеть, и лимит на один
адрес не ограничивал бы ничего): `SUBSCRIPTION_RATE_LIMIT` запросов в минуту в среднем,
всплеск до `SUBSCRIPTION_RATE_BURST` (по умолчанию 30 и 20). Считаются и ответы 404 — перебор
токенов как раз то, от чего лимит. Превышение — `429 rate_limited` с `Retry-After`.

Лимит в памяти процесса (ADR-077): панель одна, а лимит в базе стоил бы записи на каждый
запрос — ровно той нагрузки, от которой он защищает. За Caddy адрес клиента берётся из
`X-Forwarded-For`, которому панель верит только от `HTTP_TRUSTED_PROXIES`; production
compose задаёт это сам.

### Страница подписки

Та же ссылка, открытая в браузере, показывает страницу: статус, трафик, срок, кнопки
импорта в приложения, QR-код, скачивание профилей Clash и sing-box, отдельные ссылки
серверов. Язык — русский или английский по браузеру.

Решает Caddy, а не панель: запрос ровно `/sub/{token}` с `Accept`, содержащим `text/html`,
и без `?format=` получает статический `sub.html`; всё остальное проксируется в панель. Панель
остаётся чистым API и всегда отвечает профилем. То же правило повторено в dev-сервере Vite,
чтобы локально работало так же (ADR-078).

Кнопки импорта — только для приложений, чья схема ссылок документирована самим приложением
(ADR-079):

| Приложение | Ссылка | Источник |
|---|---|---|
| Hiddify | `hiddify://import/<url>#<имя>` | страница URL-схем Hiddify |
| sing-box (SFA/SFI/SFM) | `sing-box://import-remote-profile?url=<url>#<имя>` | документация sing-box, «Clients → General» |
| Clash Verge Rev и др. на mihomo | `clash://install-config?url=<url>` | документация Clash Verge Rev |
| v2rayNG | `v2rayng://install-config?url=<url>` | обсуждения в репозитории v2rayNG. [ПРОВЕРИТЬ]: по отзывам импортирует разово, без обновления подписки |

Для остальных (NekoBox, Happ, Streisand, Shadowrocket) формат ссылки не опубликован —
у них копирование и QR-код, которые принимает любой клиент.
